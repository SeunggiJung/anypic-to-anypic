Most image converters upload your file to a server, convert it there, and send the result back. This site says that all conversion happens inside the browser and that files are never sent to a server. A claim like that shouldn't depend on being believed. You should be able to **check it yourself**, and anyone can.

## Method 1: Watch the Network tab

Your browser's developer tools record every request a page makes. If a file were going anywhere, it would show up here. (These steps are for Chrome and Edge.)

1. Open this site and press **F12** to open the developer tools.
2. Select the **Network** tab. Clear the requests already listed with the Clear button (the circle with a slash through it).
3. Add an image and convert it.
4. Look at the **Method** column. A request that sends a file to a server is usually a `POST` or `PUT`. The **Fetch/XHR** filter can help narrow the list.
5. Check the request sizes too. An uploaded file would show up as roughly that many bytes sent.

On 2026-11-11, every request was recorded on the live site while a 1280×720 image was converted to JPG (Chromium driven by Playwright).

![Requests recorded on the live site: 42 while the page loads (site files, advertising domains, a Cloudflare analytics script and one POST), 6 while converting the image (all GET), 0 POST, PUT or PATCH during the conversion, and the conversion still works offline](/images/guides/request-log-live.png)

- **During the conversion**, there were 6 requests, all `GET`. There were **0** `POST`, `PUT` or `PATCH` requests, and none carried the image.
- **While the page loaded**, there were `GET` requests for the site's files and `HEAD` requests that check links. There were also requests to Google advertising domains, a Cloudflare analytics script, and **one `POST` (837 bytes)** to `anypictoanypic.com/cdn-cgi/rum`. That `POST` is Cloudflare's visit-measurement signal. It goes out once when the page opens, before any image is added, and 837 bytes is nothing next to an image of several hundred KB.

<Callout title="So is 'there is no POST' wrong?">
To be precise: **no request carrying your file goes out while an image is converted.** When the page opens, though, it does talk to the ad service and the visit-measurement tool. So when you check, look only at what happens while you add and convert an image. Clear the Network log right before adding the image, and only the requests from that stretch remain. The visit-measurement and ad tools this site uses are listed in the [Privacy Policy](/privacy/).
</Callout>

<Callout title="What are the requests you see at first?">
When the page opens, you'll see requests for the site's own files (pages and scripts). The first conversion adds a request for the script that does the conversion (the Worker), and the first HEIC conversion adds one for the decoder script. All of these fetch the site's **code**. None of them is your file going out.
</Callout>

## Method 2: Convert while offline

A site that has to send your file to a server stops working the moment the connection drops.

1. Open this site and **convert one image**, so the processing script has been downloaded.
2. In the developer tools' Network tab, choose **Offline**, or turn off Wi-Fi.
3. Without refreshing, add another image and convert it.

Conversion keeps working offline. On the same page, a 1280×720 PNG was converted to WebP while offline (52.0KB to 24.7KB). If you refresh or navigate to another page, the site itself can't load, so leave the page open while you test.

## Method 3: Look at how the site is built

This site is **static, with no code running on a server**. There is no server program to receive or process your images; the visitor's browser does the conversion. It runs on the browser's own image handling (Canvas) and a separate worker thread (Web Worker). Formats a browser can't read, such as HEIC and TIFF, are decoded in the browser using downloaded decoder code.

## What this site does store

It doesn't store your files. It does save **settings** in your browser: theme, language and your last conversion options. These stay in your device's browser (localStorage) and are not sent to a server. You can see the stored items in the Application tab of the developer tools, and clearing site data removes them. Details are in the [Privacy Policy](/privacy/).

## Using these checks on other sites

The same steps work on other converters and editing tools. Before converting something sensitive, such as an ID card, a document or a personal photo, look at the Network tab for a `POST` request. If an upload does happen, read the service's policy on how long it keeps files before you use it.
