I once had to bring 78 logos for a game to the same size and format. They came from different sources, so sizes and formats varied, and the wide logos had to keep their proportions and sit in the center. Instead of opening each file to match the canvas size, I built this converter to handle them in one pass, and I used it for that job. This guide lays out what that job needed.

Images pulled from several places into one project rarely match. A 512×512 PNG sits next to a wide JPG, and a WebP is mixed in somewhere. The engine wants a single size and format, and fixing files one at a time in an image editor takes a while.

## Decide the spec first

Settle three things before converting and the rest is easier.

- **Format**: Use PNG (or WebP) for characters, icons and UI images that need transparency. Use JPG for backgrounds and photos that don't need it and where file size matters.
- **Size**: Pick by purpose, such as 256×256 for icons and 64×64 for tiles. Many engines recommend power-of-two sizes (64, 128, 256, 512, 1024), and block-compressed textures often require multiples of 4. Check your engine's documentation.
- **Originals with a different ratio**: Choose one of the fit methods below. This choice does the most to decide how the result looks.

## Steps

1. Drag all the images in at once. You can also click to choose several, or paste an image from the clipboard with Ctrl+V. Mixed formats are fine, and each file's real format is detected automatically.
2. Choose the output format (for example PNG).
3. In the options, set Size to **Set exact size (width × height)** and enter the width and height in px. Common sizes are available as buttons.
4. Choose **How to fit** and **Image position**. The same settings apply to every file.
5. Convert, then download everything with **Download all as ZIP**. Files keep their original names; only the extension changes.

## Four ways to fit

Take a 256×128 image that needs to become 256×256.

| Method | Result | Use it when |
| --- | --- | --- |
| Keep ratio + fill the margins | Image unchanged, 64px of empty space above and below | Sprites, icons and logos whose **shape must not change** |
| Stretch or squash to fit | Stretched to twice the height, so it looks distorted | The original already has that ratio, or distortion doesn't matter (such as some textures) |
| Keep ratio + fill the frame | Sides are cropped and the square is completely filled | Backgrounds, thumbnails and card art that **must have no gaps** |
| Keep original size + center | No scaling; placed in the middle (cropped if the canvas is smaller) | You only want to **widen the canvas** of an image that is already the right size |

Converting a 256×128 image to 256×256 with "Keep ratio + fill the margins" and checking the output showed the image untouched from the 64th row to the 191st, with transparency above and below.

### Transparent margins or a color

PNG, WebP, GIF and ICO leave the margins **transparent**. JPG and BMP can't represent transparency, so the margins are filled with the **background color** (white by default). To get colored margins in PNG as well, turn on "Fill transparent areas and margins with the background color" and pick a color. If a game image needs transparency, save it as PNG, not JPG.

### Image position

The default is the center, and you can change it on a 3×3 grid. Setting character sprites to **bottom alignment** puts the feet of differently sized characters on the same line. When filling the frame, the side opposite your alignment is the one that gets cropped, so aligning a portrait to the top helps keep faces from being cut off.

- **A JPG's white background doesn't become transparent.** The converter only keeps already-transparent areas transparent. A JPG has no transparency to begin with; its background is solid white, so the white stays part of the image after conversion to PNG. If you need a transparent background, find a transparent PNG original or run the image through a background-removal tool.

## Converting many files at once

### Mixed formats are fine

A folder with PNG, JPG, WebP, HEIC, TIFF and SVG files can go in as it is. Each file's format is detected separately. If a file has the wrong extension, it is processed by its real format and the list tells you which file it was. An unsupported file is marked as an error in the list, and the rest convert normally.

### When you download a ZIP

- Result files **keep their original names**, and only the extension changes (for example `photo.heic` → `photo.jpg`).
- If files from different folders share a name, numbers are added inside the ZIP, as in `photo (2).jpg`.
- Each file shows its size before and after and the percentage change, so you can see where the savings are largest.
- You can also download files one at a time with each file's **Download** button.

## Pixel art

Ordinary scaling interpolates smoothly between pixels. That suits photos, but enlarging pixel art this way smears the edges and the pixel look disappears. Turn on **"Pixel art: scale without smoothing"** instead. It enlarges the pixels as they are, with no interpolation, so edges stay sharp. It looks cleanest at a **whole-number scale**, such as 16×16 to 64×64. At other scales, some pixels can end up wider than others.

<Callout title="Enlarging doesn't add resolution">
Stretching a small image doesn't create detail that wasn't there. If you plan to use a photo or illustration large, shrink it from the largest original you have. SVG is the exception: as a vector, it is drawn sharply at the target size.
</Callout>

## Making icons (ICO)

An ICO can be at most 256px on a side. If you ask for something larger, such as 512×512, it is still saved at 256×256 or smaller with the aspect ratio kept. For a Windows game icon or a web favicon, the simplest route is to make a 256×256 square PNG first and then convert that to ICO.

## Your settings are remembered

The format, size, fit method, position and other options you used last are remembered in this browser, so you don't need to pick them again when working to the same spec. To restore the defaults, press "Reset settings" at the top of the options. Settings are stored only in this device's browser and are never sent to a server.

## Limits to know

- Sizes are set in px only. There is no resolution setting in inches or DPI.
- Cropping only lets you choose the alignment position (nine cells). You can't pick an arbitrary region of the image to crop.
- Each file can be up to **50MB**. There is no limit on the number of files, but browser memory is finite, so a very large batch can run slower than the measurements above. For sizes that weren't measured (several hundred files or more), splitting the batch is safer.
- If HEIC files are in the batch, the first one takes a few extra seconds while the decoder downloads. Large TIFFs and very large images can fail for lack of memory. A failed file is flagged in the list and the others are unaffected.
- Animated GIF and WebP files convert only their first frame. A sprite sheet (many frames in one image) is treated as a single image, so choose the size with the frame scale in mind.
