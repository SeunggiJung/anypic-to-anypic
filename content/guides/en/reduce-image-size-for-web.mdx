When a page loads slowly or an upload hits a size limit, the usual first move is to drag the quality slider down. Other changes do more, though. The numbers below come from shrinking a smartphone photo (3000×4000, 2.6MB) with this site's converter.

## Step 1: Resize to the size you need

The biggest saving comes from not serving an image larger than it appears on screen. Smartphone photos can be 3000 to 4000 pixels wide, while a blog's text column is usually around 800. Every pixel nobody sees is still paid for in file size.

| Setting | Size | File size |
| --- | --- | --- |
| The original file | 3000×4000 | 2.6MB |
| JPG, quality 80, original size | 3000×4000 | 1.4MB |
| JPG, quality 80, width 1280px | 1280×1707 | 345KB |

Dropping only the quality to 80 at the original size takes 2.6MB down to 1.4MB. Keeping that quality and cutting the width to 1280 pixels gives 345KB, about 75% smaller. Unless you need a double-size version for high-density (Retina) screens, match the size the image is displayed at. On this site, enter a width in px under Size in the options and the aspect ratio is preserved.

## Step 2: Pick a format that suits the image

Once the size is settled, look at the format. At the same width (1280px) and quality 80, JPG was 345KB and WebP was 223KB, so WebP was about 35% smaller. The table below uses a different photo (a chicken dish, 960×1280) saved in several formats, with quality set to 90 wherever the format has a quality setting.

| Format | File size |
| --- | --- |
| WebP | 300KB |
| JPG | 343KB |
| GIF | 722KB |
| PNG | 2.6MB |
| BMP | 3.5MB |

A photo saved as PNG is more than seven times the size of the JPG, so if your site's photos are PNG, changing the format alone is the easiest win. Logos and screenshots are different. With few colors and some text, PNG is often smaller or about the same, and JPG blurs the lettering. A rule that holds up well: JPG or WebP for photos, PNG or WebP for transparency and simple graphics. [WebP vs JPG](/guides/webp-vs-jpg/) covers the difference between those two in more detail.

## Step 3: Adjust quality last

If the file is still too big after resizing and choosing a format, that's when quality comes in.

| JPG quality | File size (chicken photo, 960×1280) |
| --- | --- |
| 95 | 497KB |
| 90 | 343KB |
| 80 | 226KB |
| 60 | 146KB |

Going from 95 to 80 cuts the file by more than half (497KB to 226KB). In an enlarged comparison of a different photo (the dog), JPG 80 was hard to tell from the source by eye; see the enlarged image in [WebP vs JPG](/guides/webp-vs-jpg/). An image full of text looked different: at quality 60 the letter edges smeared (see [PNG vs JPG](/guides/png-vs-jpg/)). These figures come from single photos, so for anything important, check the size and the actual quality on the result screen.

<Callout title="Recompress only once">
Saving a JPG as a JPG again cuts quality a second time. Reduce from the original in a single pass if you can, and avoid shrinking a file that has already been shrunk.
</Callout>

## Step 4: Remove information you don't need

Camera photos carry EXIF data such as the device, the time and the location. It adds little to the file size, but it can be sensitive. Results from this site don't include it by default.

## The order at a glance

1. Resize to the displayed size. This has the biggest effect.
2. Save photos as JPG or WebP. A PNG photo shrinks a lot from the format change alone.
3. Start quality at 80 to 85 and lower it if needed.
4. Check the size and actual quality on the result screen.
